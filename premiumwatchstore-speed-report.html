Worst page: the homepage. Its Lighthouse performance score is 85 unthrottled and 29 on Slow 4G + 4× CPU. The other four pages score 99, 99, 100 and 100 unthrottled.

Three fixes that help every page at once

1. Serve the HTML from Cloudflare's cache, not from the server

The site is behind Cloudflare, but every page reply says cf-cache-status: DYNAMIC. That means Cloudflare passes each visit through to the hosting server. LiteSpeed's cache does hit (x-litespeed-cache: hit), but the first byte still arrives after 0.4–2.2 s, and that wait is the largest part of LCP on every page. Turn on Cloudflare APO for WordPress, or add a Cache Rule that caches HTML ("Cache Everything"). Bypass the cache for /cart/, /checkout/, /my-account/ and for visitors with the wordpress_logged_in_* or woocommerce_items_in_cart cookies, and purge on publish.

2. Stop CSS and fonts from holding up the first paint

Every page waits for 49 head files (714 KB) before it draws. The biggest are the theme's style.css (338 KB, which Lighthouse estimates costs 2.3 s on a budget phone) and woocommerce.css (126 KB). Google Fonts loads all 18 weights of Poppins and of Roboto plus Roboto Slab, with display=auto. In LiteSpeed Cache, turn on Generate UCSS + Load CSS Asynchronously (critical CSS inline). Self-host only the 2–3 font weights actually used, with font-display: swap. In Elementor, turn off loading Google Fonts and Font Awesome if they aren't used. Don't load dashicons.min.css for logged-out visitors.

3. Load plugin scripts only where needed, and delay tracking until the first tap

Every page loads Google "Sign in with Google" (102 KB, from Site Kit), jQuery UI datepicker and progressbar, both Select2 and SelectWoo, single-product and variation scripts, and Contact Form 7. On a budget phone that adds up to 2.15 s of main-thread blocking (TBT). Use Asset CleanUp or Perfmatters to unload them where they're unused. Turn off Sign in with Google unless customers rely on it. Use LiteSpeed's "Delay JS" for gtag, Jetpack Stats, Cloudflare Insights and WiserReview. Also serve correctly sized images: Lighthouse finds 0.4–1.5 MB of oversized images per page, mostly 800×985 product photos shown at about 500 px wide.

Budget Android user (Slow 4G, 4× CPU)

LCP fails: 7.6 s, three times the 2.5 s limit. The LCP parts are TTFB 1.35 s, load delay 0.10 s, image download 3.13 s and render delay 3.06 s. INP is 48 ms if you wait for the page to finish, but 296 ms if you tap while it loads (238 ms of that is waiting for a busy main thread). That rates "needs improvement". CLS is 0.02 and passes. Total Blocking Time is 2,150 ms across 20 long tasks.

What blocks the main thread: Elementor's carousel code (image-carousel.min.js, a single 626 ms task) and Swiper (swiper.min.js, 3.4 s of CPU). Swiper also forces layout recalculations worth about 0.6 s. Add jQuery (1.05 s), and 4.9 s of style and layout work driven by the very large CSS. Gtag, Sign in with Google and Cloudflare Insights add smaller tasks. The page only finishes loading after 27 s.

What it means: a shopper in a Tier 2 city like Patna or Surat, on a ₹8–10k phone with patchy 4G, stares at a white screen for about 7.5 s. Then the carousels keep the phone busy for another 10 s, so taps on the menu or "Buy Now" feel sluggish. Many of these visitors come from Google or ads, and some will press back before the page appears.

Layout shift and the main buttons

CLS is 0.02, which passes. There are three small shifts at about 3 s. The header logo link grows from 14 to 23 px tall (0.0001). The Elementor image carousel at the bottom of the first screen expands its slides from 2×2 px placeholders to 197×90 and 167×90 when Swiper starts, and its arrows and section collapse (0.016 + 0.004). The cause is carousel images that have no reserved size until JavaScript runs: 90 of 124 images lack width/height attributes. Fonts, banners and the WhatsApp widget caused no shifts.

A shop has no appointment button. Its main calls to action are the two Buy Now buttons (Men, Women). Both are fully visible in the first 412×915 screen and nothing covers them. The floating WhatsApp contact button is visible bottom-left, but it overlaps the customer-review images, not the buttons. There is about 110 px of empty white space between the header and the category tiles, which pushes the content down.

Method and limits

These are lab tests, not field data from real visitors. They were run from a cloud machine near Cloudflare's Virginia (IAD) location, so server times from inside India may be shorter. Tools: Chromium with Playwright and the DevTools Protocol for traces, real taps for INP, the network log, the console and screenshots, plus Lighthouse 13, whose "insights" use the same engine as the DevTools Performance panel. "Slow 4G" is 150 ms latency, about 1.4 Mbps down and 4× CPU slowdown. TTFB varied between runs (0.4–2.6 s), so repeat the tests after the fixes, and check Search Console's Core Web Vitals report for real-user data.
